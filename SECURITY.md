# Политика безопасности (Security Policy)

## 🔒 Принципы конфиденциальности VirtualMax

VirtualMax разработан по принципу **Zero-Data-Collection**:
1. Приложение не собирает, не хранит и не отправляет пользовательские данные на сторонние серверы.
2. Все сетевые трекеры (`VK`, `Mail.ru`, `Яндекс Метрика`, `WebVisor`, `Sentry`, `AppMetrica`) блокируются на нативном уровне Android и ПК еще до выхода в интернет.
3. Доступ к микрофону и камере блокируется на аппаратном уровне через тумблеры в меню настроек.
4. Внешние ссылки очищаются от трекинг-меток (`utm_*`, `yclid`, `vk_ref`, `fbclid`) перед открытием.

## 🐛 Сообщение об уязвимостях

Если вы обнаружили потенциальную уязвимость или не заблокированный эндпоинт телеметрии, пожалуйста, откройте Issue в данном репозитории.

## 🔑 Подпись релизов (CI/CD)

- Пароль ключа подписи (`mobile/keystore.jks`) **не зашит** в workflow-файлах: он передаётся
  в сборку через GitHub Secret `KEYSTORE_PASS` как переменная окружения.
- Рекомендуется хранить и сам ключ вне git — через secret `KEYSTORE_JKS` (base64), который
  перезаписывает `mobile/keystore.jks` при сборке. Приватный ключ в истории репозитория считать
  скомпрометированным: при публичном доступе его нужно ротировать.
- Для безопасной генерации нового ключа используйте `mobile/tools/rotate_keystore.sh` —
  он создаёт keystore со случайным паролем и выводит готовые значения
  `KEYSTORE_PASS`, `KEYSTORE_ALIAS` и `KEYSTORE_JKS` для GitHub Secrets.
  ⚠️ Смена ключа меняет подпись APK: уже установленные сборки потребуется удалить
  и переустановить (Android не разрешает обновление с изменённой подписью).
- CI не отправляет данные на сторонние сервисы; логи публикуются только в GitHub Actions.
