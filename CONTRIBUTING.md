## 📜 Кодекс поведения

Будьте вежливы и конструктивны. Проект не аффилирован с VK или платформой МАКС
и создаётся сообществом в исследовательских целях и для защиты приватности.

## 🐛 Как сообщить об ошибке

1. Проверьте [открытые issues](https://github.com/aiexpr/Virtual-Max/issues) —
   возможно, проблема уже известна.
2. Создайте новый issue по шаблону **«Отчёт об ошибке»**.
3. Обязательно укажите: платформу, версию приложения, шаги воспроизведения и
   ожидаемое поведение.

Для сообщений об уязвимостях используйте процесс из [SECURITY.md](SECURITY.md).

## 💡 Как предложить функцию

Создайте issue по шаблону **«Предложение»** и опишите: какую проблему решает
функция, как вы видите её реализацию и возможные альтернативы.

## 🛠️ Подготовка окружения

### Android

- JDK 17 (Temurin), Android SDK: `platforms;android-34`, `build-tools;34.0.0`.
- Сборка не использует Gradle: минимальный размер APK обеспечивает собственный
  скрипт `mobile/build.sh`.

### Desktop

- Node.js 22+ и npm.

## 🔨 Сборка и запуск

### Android (APK)

```bash
cd mobile
./build.sh          # результат: releases/VirtualMax.apk
```

Пароль/алиас подписи задаются переменными `KEYSTORE_PASS` / `KEYSTORE_ALIAS`
(в CI — из GitHub Secrets).

### Desktop

```bash
cd desktop
npm ci
npm start                     # запуск
npm run build:linux           # .AppImage + .deb
npm run build:win             # .exe (установщик) + portable
```

## 🎨 Стиль кода

- Язык комментариев и пользовательских строк — русский, имена идентификаторов —
  английские.
- Java: отступ 4 пробела, Java 8 (совместимость с `minSdk 21`), без сторонних
  зависимостей.
- JavaScript: отступ 2 пробела, `const`/`let`, без `var` в новом коде.
- XML/градиенты: брендовая палитра из `mobile/app/src/main/res/values/colors.xml`.
- Комментарии пишутся для **неочевидных** мест; объясняйте «зачем», а не «что».

Перед коммитом проверяйте синтаксис:

```bash
node --check desktop/src/main/index.js
node --check desktop/src/preload/index.js
```

## 🚫 Как добавить домен в блок-лист

Блокировка трекеров реализована в двух местах — не забудьте обновить **оба**:

1. **Android** — `mobile/app/src/main/java/com/virtualmax/privacy/PrivacyInterceptor.java`,
   множество `BLOCKED_HOSTS` (суффиксный матчинг по доменным меткам) и
   `URL_PATTERNS` (правила по хосту+пути).
2. **Desktop** — `desktop/src/main/blocklist.js`, массивы доменов.

Требования к записям: нижний регистр, без протокола и пути, без wildcard-звёздочек
в Android-списке (суффиксный матчинг покрывает поддомены автоматически).

⚠️ Не блокируйте домены, необходимые для работы самого мессенджера
(`web.max.ru`, CDN-хосты МАКС) — иначе клиент перестанет работать.

## 🔀 Процесс Pull Request

1. Создайте ветку от `main` и внесите изменения.
2. Обновите `CHANGELOG.md` (секция `[Unreleased]`) и, при необходимости, README.
3. Проверьте сборку (см. выше).
4. Откройте Pull Request по шаблону; укажите, что и зачем меняется.

Правила:

- Один PR — одна логическая задача.
- Бинарные артефакты (`*.apk`, `*.ico`, `*.jks`) не изменяются вручную —
  они генерируются скриптами/CI.
- Изменения подписываются и проходят ревью перед слиянием.
